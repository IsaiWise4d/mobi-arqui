# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-page marketing landing for **Mobi Arquitectura** (carpentry, furniture design, and civil works), built with Astro 5 as a static site. All copy is in Spanish. The current target market is Barranquilla, Colombia (`lang="es-CO"`). The repo folder is named `movi`, but the brand is "Mobi". The main conversion path is click-to-chat on WhatsApp.

## Commands

The package manager is pnpm (`pnpm-workspace.yaml` allows the esbuild/sharp builds). A `package-lock.json` also exists, but `node_modules` is pnpm-managed.

- `pnpm dev`: dev server at http://127.0.0.1:4321/
- `pnpm build`: static build into `dist/`
- `pnpm preview`: serves the build

There are no tests, linter, or formatter.

Visual QA: with the dev server running, run `node tools/capture.mjs` (`BASE_URL` overrides the URL). It uses puppeteer-core with the first installed Edge or Chrome (`BROWSER_PATH` overrides) and writes desktop (1440), mobile (390), reduced-motion, and per-section screenshots into `.impeccable/review/` (gitignored). It also exercises the cotizador wizard and opens an FAQ item. If you rename or add section `id`s, update its `SECTIONS` list.

## Architecture

- `src/pages/index.astro` is the whole page: `<head>` (SEO meta, JSON-LD), the fixed header (`.cajetin`), the hero, and the footer. Its one `<script>` imports the client modules in `src/scripts/`:
  1. `hero-sequence.ts`: the **hero scroll-scrubbed canvas sequence** (config in `HERO_SEQUENCE`). Scroll progress through the tall `#inicio` section picks a frame index drawn to `<canvas id="scrub">`. The same progress drives the overlay layers (intro → HUD → `#heroBridge` CTA) via `copyStops`, and the HUD ruler via `--p`. Frames are fetched as blobs coarse-to-fine, nearest the playhead first; only a budget of `ImageBitmap`s around the playhead stays decoded. The rAF loop runs only while easing toward the target. It handles reduced-motion and Save-Data (final frame only), load-failure fallback, and a `noscript` image. The poster (`#heroPoster`) is plain HTML so it is the LCP element.
  2. `nav.ts`: header hide-on-scroll and the mobile section menu.
  3. `motion.ts`: the Embla carousels and the reveal IntersectionObserver (adds `.in`; CSS does the motion). There is no animation library. The process line is a CSS scroll-driven animation with an `.in` fallback, the gallery photo swap in `Proyectos.astro` uses View Transitions, and the menu uses `@starting-style`.
- `src/components/*.astro` hold one section each, rendered in order after the hero in `index.astro`. Component scripts and styles are minimal; styling lives almost entirely in the single global stylesheet `src/styles/global.css` (design tokens are on `:root`).
- `src/data/sitio.ts` is the **editable content source**: brand, WhatsApp number plus `waLink(mensaje)`, services, indicators, projects (with photo lists), the Instagram reels shown in section 05 (`instagramPosts`, covers in `public/instagram/`; no like/comment counts), FAQ, the about-us text, and the quote-wizard options. Components import from here. Lines marked `🔶` are values still unconfirmed with the client.
  - Some strings are still hardcoded outside it, for example "Barranquilla, Colombia" in `Contacto.astro`, the footer, and hero/meta copy in `index.astro`. When changing city/brand facts, grep `src/` as well as editing `sitio.ts`.
- `Cotizador.astro` is a multi-step quote wizard (`.wz-step`, `.wz-chip` radio chips). It builds a WhatsApp message from the answers; there is no backend or form submission.

### Hero frame assets

- `public/seq/desktop/f-001..300.webp` (1920×1080) is the desktop sequence. `public/seq/mobile/f-001..150.webp` (720×960, ≤700px) is the mobile one, sampled from the 300; `sourceFrame()` maps it back for the counter.
- `public/seq/stills/` holds the service-card images (referenced in `sitio.ts`) and `public/og.jpg` the Open Graph image. Frame 300 is the `noscript` image and the fallback.
- All of these are generated by `tools/encode-frames.mjs` (sharp). Its 4K sources were `public/frames/` and `public/frames-webp/`, which are no longer in the tree; recover them from git history (instructions in the script header).
- They are WebP, not AVIF, because the scrub decodes continuously and AVIF decodes much slower. If you re-encode, change the folder name (e.g. `/seq-v2/`): `public/_headers` caches `/seq/*` as immutable.
- `Plano_arquitect_nico_cobra_vida__...frames/` at the repo root is the untracked raw source (gitignored). Don't commit it.
- Rights to the source video are unconfirmed (see DESIGN.md). Don't redistribute the frames as a new asset without asking.

### SEO

`SITE_URL` in `astro.config.mjs` (🔶 domain not yet confirmed) sets `site`, which enables canonical, `og:url`, absolute `og:image`, and the sitemap entry. `src/pages/robots.txt.ts` and `sitemap.xml.ts` are static endpoints.

## Design and product docs

- `DESIGN.md` defines the visual system, "El plano técnico": the page reads as an architect's drawing sheet, with paper background, fine grid, hairlines, mono annotation labels, and a sello-style CTA.
  - Hard rules: no border-radius, no generic box-shadows or elevated cards, and the dark `--noche` background appears only in the hero.
  - Fonts: Saira Semi Condensed for titles and sellos, Archivo for body text, Fragment Mono for labels/codes (all via `@fontsource`, imported in `index.astro`).
- `PRODUCT.md` covers audience, positioning, and principles. The key principle: **never invent projects, testimonials, clients, metrics, or prices.** Real project photos live in `public/proyecto1/` and `public/proyecto2/` (sourced from the brand's Instagram).
- `mobi-copy-definitivo.md` is the approved section-by-section copy. Check it before rewriting any copy.
- Parts of DESIGN.md and PRODUCT.md are stale compared with the code. `global.css` and `sitio.ts` are the source of truth:
  - The docs still say Mexico, a pending WhatsApp number, a portfolio placeholder, amber `#b97a3f`, and a 64px header.
  - The code now has Colombia, a live WhatsApp number, real projects, `--ambar` pointing to teal `#0d7688`, and `--header-h: 82px`.

## Tooling in the repo

`.agents/skills/` and `.opencode/` contain vendored agent skills (impeccable, frontend-design, responsive-design, scroll-scrubbed-visual-sequence, ui-ux-pro-max), tracked by `skills-lock.json`. `.impeccable/` holds that tool's state and the landing surface brief (`.impeccable/surfaces/landing.md`). These are tooling, not site code. Leave them alone unless you are working on the tooling itself.
